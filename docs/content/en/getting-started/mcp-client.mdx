# Connect governed MCP tools

Register a tenant-scoped MCP server using Streamable HTTP or stdio. Discovery is explicit and
only discovered tools can be invoked. The client also discovers resources and prompts. Authentication
supports none, API key, Bearer/OAuth/OIDC tokens and custom headers; secrets stay in runtime memory
and are never returned by the registry.

## Prerequisites

- A server owned by the same organization and a restricted MCP credential.
- `mcp.use` and `capability.execute` granted to the calling principal.
- A published AgentVersion when tools will be used by an agent.

## Steps

1. Register the server with its transport and authentication policy.
2. Call `tools/list` through `discover` and review the returned schemas.
3. Materialize the discovered tools with `registerCapabilities`; they are AGENT-only capabilities.
4. Include the capability names in the AgentVersion allowlist and run through AgentHarness.

If the remote server restarts or its stdio process becomes unusable, call `reconnect` with the
organization and server identifiers. This closes the current transport without retrying the
possibly non-idempotent tool call; the next discovery or call creates a fresh transport while
preserving the registered server and discovery cache.

The equivalent CLI operation is `handstack mcp reconnect --server <server-id>`.

## Verify

Confirm the HTTP Authorization header uses the configured scheme, cross-organization calls fail,
undiscovered tools are rejected, and an agent tool call emits the normal capability audit and
budget events.

## Troubleshooting

- `MCP tools must be discovered first` means discovery has not completed for this server.
- Permission denial means the principal lacks every permission required by the server/tool.
- HTTP and stdio protocol errors are sanitized; inspect server logs using the request id.
