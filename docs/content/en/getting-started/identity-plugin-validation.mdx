# Validate identity provider metadata before registration

## Prerequisites

- A plugin host with an identity provider registration callback.
- A descriptor with a stable provider ID, display name, capabilities, configuration schema and unique permissions.

## Steps

1. Register the provider from plugin setup.
2. Let the host call `validateIdentityProviderRegistration` before forwarding the descriptor.
3. Accept organization configuration only after registration validation and host policy.

## Expected results

Invalid IDs, empty metadata, empty schemas or duplicate permissions fail before the host callback and create no side effect.

## Verify

Run the Plugin SDK contract tests and confirm malformed identity metadata fails closed.

## Troubleshooting

- `Identity provider permissions must be unique and non-empty` means authorization metadata is incomplete or duplicated.
- `Identity provider configuration schema is required` means the provider cannot be safely configured.
