# Operate bounded background jobs

HandStack queues separate agents, embeddings, documents, plugins, webhooks, audit, billing,
cleanup and indexing workloads. Each queue has bounded backlog, priority, retries with jitter,
timeouts, idempotency and dead-letter retention.

## Prerequisites

- Run dedicated workers for agents, knowledge, integrations, webhooks, audit/billing and maintenance.
- Configure queue capacity, concurrency, retry limits and retention for the deployment profile.

## Steps

1. Enqueue with an idempotency key and reject at capacity with `Retry-After`.
2. Process with cancellation, heartbeat and checkpoint hooks.
3. Retry transient failures with exponential backoff; inspect and retain terminal DLQ jobs.
4. Gracefully stop workers only after completing or returning the active job.

## Verify

Test duplicate enqueue, capacity backpressure, retry/DLQ transitions, timeout and cancellation.

## Scrape worker metrics

The worker exposes Prometheus text format at `GET /metrics` on
`HANDSTACK_WORKER_METRICS_PORT` (default `9091`). The endpoint contains aggregate active,
completed, failed and heartbeat metrics only; job payloads are never included. Put the metrics
port behind the platform network policy and configure Prometheus to scrape each worker instance.

## Troubleshooting

- A backpressure error is intentional protection against unbounded memory; honor its retry delay.
- Keep queue payloads small and store large artifacts in object storage.
