# Encrypt secrets at rest with the master key

HandStack encrypts sensitive values at rest with AES-256-GCM. A single 256-bit master key is loaded
from the `HANDSTACK_MASTER_KEY` environment variable, and every ciphertext is additionally bound to
its organization and plugin context so a sealed value cannot be opened from another tenant. Purpose
keys are derived from the master key with HKDF-SHA256, and plaintext, key material, and ciphertext
are never written to logs or error messages.

## Prerequisites

Hold the `secrets.manage` permission and access to the deployment environment where the master key
is stored. The master key must be 32 bytes encoded as base64 (standard or URL-safe) or as a 64-digit
hex string.

## Steps

1. Generate a 32-byte master key and encode it as base64; store it only in a secret manager or
   environment variable, never in source control.
2. Set `HANDSTACK_MASTER_KEY` to that value before starting the process.
3. Load the key with `MasterKey.fromEnvironment()` and derive the `secret-encryption` purpose key.
4. Seal each secret with `sealSecret(value, key, secretAad({ organizationId, pluginId }))` and store
   only the returned envelope.
5. Open a secret with `openSecret(envelope, key, secretAad(sameContext))`; use `EncryptedSecretStore`
   to keep envelopes tenant-bound and open them through the `SecretProvider` boundary.

## Verify

Sealing the same value twice produces different envelopes that both open to the original value.
Opening with a different key, a different organization, or a tampered envelope fails with a redacted
`EncryptionError`, and no error or stored envelope contains the plaintext.

## Troubleshooting

A `DECRYPTION_FAILED` result means the key, the AAD context, or the ciphertext differs from sealing;
rotate only through a supported re-encryption job, never by editing envelopes in place. An
`INVALID_MASTER_KEY` result means `HANDSTACK_MASTER_KEY` is missing or does not decode to 32 bytes;
regenerate or re-encode the key and restart the process.
