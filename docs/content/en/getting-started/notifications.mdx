# Deliver tenant-scoped notifications

Notifications are organization-scoped and delivered through replaceable providers: in-app storage,
SMTP email, and signed webhook transport. Plugin channels such as Slack, Teams and Discord implement
the same `NotificationProvider` boundary without coupling the core to a vendor SDK.

## Prerequisites

Hold the `notifications.manage` permission and configure the target channel transport.

## Steps

1. Build a notification with recipient, channel, subject and body.
2. Dispatch through the matching provider.
3. For email, configure `HANDSTACK_SMTP_*`; `HANDSTACK_SMTP_PASSWORD_REF` is resolved on demand
   through the tenant-scoped Secrets broker (`secret://` or allow-listed `env://` reference). Never
   put the password in notification content or a queue payload.
4. For webhooks, provide an endpoint fetcher with bounded request and response sizes; its abort
   deadline uses the configured `timeouts.http` value.

## Verify

Notifications append idempotently, list per recipient within the organization, and duplicate ids are
ignored.

## Troubleshooting

If delivery fails, check the transport configuration and timeout limits. Never include secrets in
notification bodies.
