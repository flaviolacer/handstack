# Armazenar configuração de plugin de identidade por tenant

## Prerequisites

- Um plugin de identidade registrado e um administrador da organização.
- Um ID de secret do HandStack ou uma referência de ambiente como
  `env://HANDSTACK_SECRET_OIDC_CLIENT` para campos confidenciais.

## Steps

1. Crie um `InMemoryIdentityProviderConfigurationStore` para uso local/offline ou implemente o mesmo contrato para armazenamento durável.
2. Defina a configuração com `organizationId` e ID do provedor.
3. Armazene o valor pela API de Secrets do tenant e use `secret://<id-retornado>`, ou provisione uma
   variável de ambiente `HANDSTACK_SECRET_*` e use `env://<nome-exato-da-variável>`.
4. Use somente essas referências nos campos confidenciais do provedor de identidade. O runtime as
   resolve pelo broker de segredos no mesmo escopo de organização e provedor.

## Expected results

A configuração não pode ser lida entre organizações, escopos vazios falham fechados e valores
confidenciais inline são rejeitados. Secrets persistidos são criptografados e vinculados ao
tenant/plugin; referências de ambiente são restritas ao namespace e auditadas sem registrar valores.

## Verify

Execute os testes de contrato do plugin SDK e confirme que uma organização diferente não retorna configuração.

## Troubleshooting

- `Identity provider secret field ... must be a reference` indica valor confidencial inline.
- `Identity provider configuration scope is invalid` indica ID de organização ou provedor inválido.
