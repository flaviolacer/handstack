# Usar APIs governadas de operações

A API expõe operações tenant-scoped em `/api/v1/organizations/:organizationId`. Todo endpoint
exige bearer token, organização coincidente e decisão explícita de permissão.

## Prerequisites

- Conceda `feature-flags.read/manage`, `audit.read` ou `jobs.manage` pela policy de identidade.
- Configure Redis/BullMQ e audit durável em produção.

## Steps

1. Use `GET/PUT /feature-flags/:key` para overrides de organização/usuário.
2. Use `GET /audit` para evidência append-only da organização atual.
3. Use `GET /audit/verify` para verificar a cadeia de hashes tamper-evident do tenant. A operação
   grava um evento `AUDIT_VERIFIED` com contagem e validade, sem expor segredos de auditoria.
4. Use `POST /jobs/:queue` com chave de idempotência para enfileirar trabalho limitado.

## Verify

Requests cross-tenant, tokens ausentes e permissões negadas devem falhar. Capacidade da fila retorna
backpressure tipado; audit nunca devolve outro tenant. A verificação exige `audit.read` e retorna
os campos `valid`, `checked` e `errors` limitados.

## Troubleshooting

- Erro de permissão exige concessão administrativa do escopo exato.
- Workers processam jobs; a API apenas enfileira e não drena filas locais.
