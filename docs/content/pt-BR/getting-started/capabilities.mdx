# Publicar e executar capabilities

Capabilities são contratos executáveis por tenant com schemas de entrada/saída, canais
permitidos e handler. Adaptadores de API, Web, MCP e Agents devem usar o mesmo engine governado.

## Prerequisites

- Membro autenticado com `capability.execute`.
- Capability registrada com `API` (ou o canal do adaptador) na publicação.

## Steps

1. Registre slug, schemas, timeout, permissões e canais de publicação estáveis.
2. Resolva com `GET /api/v1/organizations/{organizationId}/capabilities`.
3. Execute com `POST /api/v1/organizations/{organizationId}/capabilities/{slug}/run`.

Para uma capability que trata dados pessoais, defina `metadata.consentPurposeId` com o ID de uma
finalidade de privacidade persistida. O engine verifica o consentimento mais recente do principal
autenticado antes da execução e falha fechado após a retirada. Destinos externos continuam exigindo
classificação, provider e metadados explícitos de residência.

## Verify

Confirme resultado para chamada autorizada e 403 para permissão ausente ou outro tenant.
Confirme falha fechada quando o canal não estiver publicado.

## Troubleshooting

- `capability.execute permission is required` indica permissão ausente.
- `Capability is unavailable` indica slug ou canal não publicado.
- Timeout e abort liberam a reserva de budget antes do erro.
- `Consent is not granted for purpose ...` indica que o principal precisa conceder a finalidade de
  privacidade declarada antes de executar a capability.
